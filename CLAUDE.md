## What this is

A Vaadin Flow add-on library (packaged as a Maven JAR) that wraps the third-party
[VisActor VTable](https://visactor.io/vtable) JavaScript library, exposing it as a server-side
Java `PivotTable` component. It is published to GitHub Packages, not run as a standalone app —
consuming projects depend on `com.inttao.apps.vaadin.components.vtable:pivot-table-component`.

- Java 21, Vaadin 24.5.0 (see `vaadin.version` in `pom.xml`).
- Maven wrapper is committed (`./mvnw`).

## Commands

```bash
./mvnw clean install            # build + install the JAR to the local repo
./mvnw clean package -Pproduction   # production build (runs Vaadin build-frontend to bundle the frontend)
./mvnw deploy                   # publish to GitHub Packages (needs vtable-repo creds, see below)
./mvnw verify -Pit              # integration tests via TestBench/failsafe (no tests exist yet)
```

There is no single-test command configured because the project currently has no tests
(`vaadin-testbench-junit5` is declared but unused). The `defaultGoal` is `spring-boot:run`, but
`App.java` is only a stub `main` with a `@Theme` annotation — there is no `@SpringBootApplication`,
so this is a library, not a runnable application.

### GitHub Packages auth

Both consuming and deploying require a `<server>` named `vtable-repo` in `~/.m2/settings.xml`
with a GitHub username + personal access token (read:packages / write:packages). See `README.md`
(in Spanish) for the exact snippet. The repo URL is
`https://maven.pkg.github.com/aventurasoft/vaadin-vtable-component`.

## Architecture

The entire component is two source files plus a bundled JS library.

**`PivotTable.java`** (`src/main/java/.../vtable/`) — the only meaningful class. It extends Vaadin's
`Div` and works by generating a JavaScript object literal and executing it in the browser:

1. The constructor assigns a random `UUID` as the element's DOM id, sets min size, and loads the
   VTable library via `UI.getCurrent().getPage().addJavaScript("./frontend/vtable.min.js")`.
2. `generateOptions()` builds the VTable `option` object as a **string** of JS/JSON.
3. `setupTable()` must be called explicitly to render — it runs
   `getElement().executeJs("const option = {...}; new VTable.PivotTable(document.getElementById(id), option)")`.
   The constructor alone renders nothing.

Key consequence: most setters (`setRecords`, `setIndicators`, `setCorner`) take **raw JS/JSON
strings that are concatenated verbatim** into the options literal — they are not escaped or
validated. Only `columns`/`rows` go through Jackson (`objectMapper.writeValueAsString`). Callers
are responsible for passing syntactically valid JS/JSON. The fields map directly to VTable's pivot
table config options (see the linked VTable docs in the class Javadoc).

Note the misspelling: `withMode` / `getWithMode` / `setWithMode` corresponds to VTable's
`widthMode` option.

**`vtable.min.js`** — the ~1.3MB bundled VisActor VTable library, the canonical copy lives at
`src/main/resources/META-INF/resources/frontend/vtable.min.js` and is served as a Vaadin static
frontend resource. Copies under `frontend/`, `frontend/generated/`, and `target/` are produced by
the Vaadin build — do not hand-edit those; change the `src/main/resources/...` copy.

**`App.java`** — a near-empty stub carrying only the `@Theme(value = "myapp", variant = Lumo.DARK)`
annotation.

## Generated / untracked files

`frontend/`, `frontend/generated/`, `src/main/bundles/`, `package.json`, `package-lock.json`,
`vite.config.ts`, and `target/` are all generated by the Vaadin Maven plugin (`prepare-frontend` /
`build-frontend`). Don't treat them as source.
